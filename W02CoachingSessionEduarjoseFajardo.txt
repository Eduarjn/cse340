500 for that specific user, while the server stays up for everybody else.

Here is the last piece of the puzzle. The path the data takes is basically the
server "packing" the information and EJS "unpacking" it when it builds the
screen.

That object { title, projects } works exactly as that transport package (the
view context). As you noticed with the shorthand, it is the equivalent of
{ title: 'Service Projects', projects: projects }. It groups the variables that
live on the Express server and sends them to the view layer.

The flow works like this:

1. The route takes the array returned by getAllProjects() and puts it inside
that object.

2. res.render starts the EJS engine, handing it the projects.ejs file and that
"package" of data.

3. Behind the scenes, EJS unpacks that object and turns its keys into local
variables available inside the template.

4. That is why, on line 7 of the file, <% projects.forEach %> works. EJS
recognizes the projects variable, loops over the array and, for each item, puts
the value on the screen using the output tag <%= project.project_name %>. After
it processes the whole loop and builds the final HTML, then the page is sent
back to the user's browser.

COACH:

The flow is described accurately. You used a useful metaphor - "packing" and

EDUARJOSE:

Great hint. Thinking about the final HTML, the difference becomes very clear:
it is the difference between "running logic" and "printing data".

The <% tag (line 7) is used purely for control flow and logic on the server,
like our forEach loop or an if block. EJS runs the JavaScript inside it, but it
does not print anything in the resulting HTML. The user will never see the code

The <%= tag (line 9, with the equals sign) is an output tag. The = tells EJS:

COACH:

Correct and well explained. Let me complete the set of three so you have the
whole picture:

    <% %>   -> runs logic, prints nothing
               (the forEach on line 7)

    <%= %>  -> prints the value WITH HTML ESCAPING
               (<%= project.project_name %>)

    <%- %>  -> prints the value WITHOUT ESCAPING
               (<%- include('partials/header') %>)

The difference between <%= and <%- is about security. <%= converts dangerous
characters before printing - if a value from the database contains a script
tag, it becomes visible text instead of an executable script. That protects you
from XSS. <%- prints the raw value, and that is why it is used with include:
there you WANT the HTML of the header to be interpreted as HTML.

The practical rule: use <%= for any data that came from the database or from
the user; use <%- only for HTML that you control yourself.
